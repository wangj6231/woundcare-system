# 小傷口重疊切片推論實驗（2026-09-14）

這是依照上一輪錯誤分解執行的單因素 **development diagnostic**。固定 D-Seg-03R 權重，只把 512×512 validation image 切成四個 384×384 區域，起點為 (0,0)、(128,0)、(0,128)、(128,128)，切片之間重疊 256px；各切片使用 `imgsz=768`，再將框映射回 512px 並以 NMS IoU=0.70 合併。

資料仍為同一 FUSeg validation：191 張、186 張有傷口、5 張無傷口、241 個 GT instances。`test_images_used=0`；沒有訓練、沒有讀 test、沒有替換 App 權重。

## 結果

主設定為 confidence=0.10、bbox matching IoU≥0.50：

| 指標 | 全圖 D-Seg-03R (`imgsz=768`) | 四切片 |
|---|---:|---:|
| TP / FP / FN | 200 / 27 / 41 | 203 / 84 / 38 |
| Precision | 88.11% | 70.73% |
| Recall | 82.99% | 84.23% |
| F1 | 85.47% | 76.89% |
| 小傷口 Recall | 73.72% | 75.18% |
| 裁切保留至少 95% 傷口像素 | 88.17% | 89.78% |

完整 confidence 網格（0.05、0.10、0.15、0.25、0.40）皆保留於 `outputs/tiled_inference_20260914_r3/result.json` 與 `metrics_conf*.json`。confidence=0.40 時 F1 仍約 81%，未達事前「F1 不得下降超過 1 個百分點」的採用規則。

四切片的 20 張 GPU 測量平均 146.79 ms/張，約 6.81 FPS；不含讀檔、HTTP、分類器。相較全圖約 47.83 ms/張，延遲約增加三倍。

## 決策

切片確實略微改善小傷口 Recall（+1.46 個百分點）與裁切完整率（+1.61 個百分點），但帶來大量重疊框誤報（FP 27→84）並使 F1 下降 8.58 個百分點。因此不啟動 tiled-training、不採用切片推論作為 App 預設；後續若要研究，必須先設計更嚴謹的跨切片合併/去重策略，且仍需在未使用資料上驗證。

第一次實作因錯誤的切片起點而在第一張影像被攔截，第二次因輸出欄位介面錯誤被攔截；失敗證據保留在 `outputs/tiled_inference_20260914/` 與 `_r2/`，未進入正式數字。修正後的 `_r3/` 才是唯一完整結果。
